# 龙妖首板基因识别器 · v2

> 底层策略：龙妖战法 ｜ 目标任务：**首板识别 + 次日开盘介入**
> 预测目标：**首板次日 1 进 2 晋级概率**（Y=1 晋级成龙 / Y=0 一日游断板）

---

## 一、系统架构

```
build_dataset.py      离线数据集构建（四大基因 12 因子、样本清洗、时序切分）
model_train.py        网格搜索训练多因子加权打分模型，输出最优权重
dragon_analyzer.py    因子打分 + 情绪周期折扣 + 一票否决失效判定（核心）
flask_server.py       Flask 后端（内置盘中调度、竞价二次校验、扫描日志）
index.html            网页可视化看板（纯前端，自动刷新）
config.json           模型参数（最优权重 / 分位箱 / 校准表 / 评估指标）
```

**模块划分**

| 模块 | 说明 |
|---|---|
| 离线训练模块 | 拉取历史涨停数据 → 构建首板样本库 → 网格搜索最优因子权重 → 评估 + 过拟合校验 |
| 盘中实时推理模块 | 定时扫描当日非一字首板 → 基因打分 → 情绪周期折扣 → 失效信号判定 → JSON 接口 |
| 自动迭代模块 | 收盘自动入库当日样本 → 次日回填标签 → 每月轻量重训练 / 每季完整网格搜索 |

## 四、四大基因模块（12 因子）

| 模块 | 权重范围 | 因子 | 方向 | 含义 |
|---|---|---|---|---|
| **1 板块基因** | 10~40 | `plate_strength` | + | 板块涨停数占全市场比例（主线强度） |
| | | `plate_has_leader` | + | 板块内存在 2 板以上高位龙头 |
| | | `plate_limit_cnt` | + | 板块当日涨停家数 |
| **2 量价基因** | 10~40 | `rel_turn` | + | 相对换手：当日换手 / 近 20 日均换手 |
| | | `volume_ratio` | + | 涨停前量比：当日量 / 近 5 日均量 |
| | | `bomb_times` | − | 炸板次数（尾盘炸板扣分加倍） |
| | | `price_pos` | − | 近 30 日累计涨幅（高位首板压分） |
| **3 筹码资金基因** | 5~25 | `chip_pressure` | − | 上方套牢筹码压力（60 日成交额加权） |
| | | `big_money_net` | + | 主力大单净流入估计 |
| **4 市场情绪基因** | 5~20 | `market_emotion` | + | 涨停家数 + 连板高度 − 炸板率 |
| | | `high_limit_premium` | + | 昨日涨停股今日平均溢价 |
| | | `bomb_rate` | − | 全市场炸板率 |

打分公式：

```
Score = w1·S_板块 + w2·S_量价 + w3·S_筹码 + w4·S_情绪        （各模块 0~100）
S_模块 = Σ(子权重 × 子因子分位分) / Σ子权重
```

## 五、情绪周期与一票否决

**情绪周期 4 档（动态加权，优先级高于打分）**

| 档位 | 判定条件 | 折扣 | 门槛 |
|---|---|---|---|
| 主升 | 连板高度≥6 且 涨停家数≥60 且 炸板率<30% | ×1.0 | 70 |
| 震荡 | 其余情形 | ×0.8 | 70 |
| 退潮 | 炸板率>45% 或 连板高度≤3 | ×0.5 | **80** |
| 冰点 | 涨停家数<20 或（连板≤2 且炸板率>50%） | 暂停筛选 | — |

**一票否决 · 失效信号（触发即剔除候选池）**

1. 盘中主线切换、个股脱离主线（板块涨停家数 < 2 → 总分打 7 折）
2. 封单持续快速崩塌（较上轮扫描衰减 > 35%，或封单 < 流通市值 0.3%）
3. 反复炸板 ≥3 次 / 尾盘炸板（14:30 后）无法回封
4. 次日 9:25 竞价核按钮、大幅低开（< −3%）→ 直接移出观察池

**入选规则**：总分 ≥70 → 优质首板，纳入次日开盘观察池；55~69 → 备选；<55 → 剔除。

## 六、数据集与训练规范

**预测标签**：Y=1 首板次日成功晋级 2 板；Y=0 断板。

**样本清洗**：剔除 ST / 退市 / 上市不足 20 日新股 / 一字首板 / 复牌一字 / 大盘权重股（流通市值 > 500 亿）/ 大盘单日暴跌 > 5% 的当日样本 / 近 5 日出现过跌停的暴雷标的 / 因子残缺样本。

**时序切分（禁止随机 shuffle）**

| 集合 | 区间 | 用途 |
|---|---|---|
| train | 2023.01 ~ 2025.12 | 网格搜索权重 |
| valid | 2026.01 ~ 2026.06 | 筛选最优参数、防过拟合 |
| test | 2026.07 ~ 今 | 训练阶段不可见，仅最终评估 |

**评估指标**：Precision（晋级率，核心）、Recall、AUC、样本平均次日盈亏、最大回撤；
**过拟合校验**：训练集与验证集精确率差值 > 15% 自动舍弃该组权重。

## 八、自动化运维

- **盘中**：9:15 ~ 15:00 每 **15 分钟**扫描一次首板（内置调度线程，无需外部定时任务，非交易时段完全静默）
- **收盘**：15:10 自动入库当日首板样本 → `data/daily_samples_YYYYMMDD.csv`（次日回填标签）
- **重训练**：每月执行 `build_dataset.py --skip-download` + `model_train.py` 做轻量更新；每季度完整重跑下载与网格搜索
- **日志**：`logs/scan_YYYYMMDD.log`（每轮扫描时间 / 标的分数 / 失效告警）、`logs/build_dataset.log`、`logs/model_train.log`
- **错误处理**：接口拉取失败自动重试 3 次并打印日志，不中断主流程

## 九、数据源与重要限制

> ⚠️ **akshare 属于网页爬虫数据源，盘中存在延迟，精细封单数据有限；
> 本系统用于策略原型验证，不直接等同于实盘交易依据。**

> ⚠️ **严格禁止使用未来函数：任何因子计算只能使用当日及之前已产生的数据。**

数据源：
- 新浪日 K `stock_zh_a_daily`（深度历史全量 OHLCV + 流通股本，主数据源）
- 新浪行业 `stock_sector_detail`（83 个行业板块成分股）
- 东财涨停池 `stock_zt_pool_em`（近 15 日富因子：封板时间 / 炸板次数 / 封单额）
- 东财炸板池 `stock_zt_pool_zbgc_em`（当日炸板家数）
- 交易所股票清单 `stock_info_a_code_name`（ST 识别）

**已知取舍**：东财 `push2` 系列域名在部分网络环境被限流，因此深度历史样本的「板块热度」与「主力资金」采用日 K 推导的等价代理指标（代码内已注明）；网络恢复后重跑即可用更精细数据覆盖。

## 服务启动方式（手动，无自启动）

**不开机自启**：已移除注册表启动项与计划任务，只在需要时手动启动，避免后台常驻占用网络。

- 启动：双击 `run_server.bat`，或运行 `python flask_server.py`（守护版：`python autostart_server.py`，端口已被占用时自动跳过）
- 停止：任务管理器结束 `flask_server.py` 进程，或 `taskkill /F /IM python.exe`

## 网络占用策略（低流量，已按用户要求配置）

| 时段 | 行为 | 网络请求 |
|---|---|---|
| 交易日 09:15–15:00 | 盘中扫描，间隔 **15 分钟** | 每轮约 40 次（涨停池 + 逐股日 K） |
| 15:10 | 收盘入库 | **0 次**（直接落盘最后一轮缓存） |
| 15:00 之后 / 09:15 之前 | 完全静默 | **0 次** |
| 周六周日 | 完全静默 | **0 次** |

- 看板 60 秒自动刷新**不会**触发重复扫描：距上一轮不足 15 分钟时直接返回缓存
- 非交易时段调用 `/api/analyze` 走离线数据集（不联网），需实时数据请加 `?force=1`
- 历史数据已全量缓存于 `data/bars_shard*.csv`，日常无需批量下载（禁止高并发下载）
