## 零、总体结论

| 维度 | 判定 | 依据 |
|---|---|---|
| 预测能力 | **未证明存在** | test AUC = **0.4978**（随机 = 0.5） |
| 评分排序能力 | **已被自身数据证伪** | 校准表 [65,70)=25.14% → [70,75)=**16.32%**，单调性违反 2 次 |
| 收益口径 | **不可实现** | `ret_next_oc` 均值 −0.296%，且 7.33% 样本次日涨停开盘物理上买不到 |
| 因子有效性 | **2 个因子数学上无效** | `big_money_net` 恒等退化；`bomb_times` 训练集 100% 缺失 |
| 回测可信度 | **不可信** | 无交易成本、无滑点、无资金约束、无 Walk-Forward、无基线 |
| 数据正确性 | **有系统性缺陷** | 不复权、时点无效股票池、无质量检测 |
| 可复现性 | **不满足** | 双路径产数据集不一致；无决策日志 |

**一句话**：v2 的四层地基（数据 / 标签 / 回测 / 评分）同时存在问题，且**底层错误会向上层传播**——
在 `big_money_net` 退化和 `ret_next_oc` 不可实现的前提下，任何权重优化都是在噪声上做的优化。
因此 v3 的顺序必须是：**先修回测与数据 → 再做因子与模型**。

## 一、A 级问题（致命 · 影响结论成立与否）

### A1 · `big_money_net` 因子在数学上完全退化 ⚠️ 最严重

**位置**：`build_dataset.py:434-441`

```python
rng = cur["high"][pos] - cur["low"][pos]
if rng > 0:
    mf = ((r["close"] - r["low"]) - (r["high"] - r["close"])) / rng
...
big_money = float(mf * r["amount"] / a20 * 100)
```

**机理**：样本定义要求「收盘封板」，即 `close >= lim` 且 `close >= high`（`build_dataset.py:306-307`）。
封板股的 `close == high`，代入上式：

```
mf = ((close−low) − (high−close)) / (high−low)
   = ((high−low) − 0) / (high−low)
   = 1.0    （恒等）
```

**实证**（`docs/audit_evidence.txt` 检查 2，11,318 条可匹配样本）：

```
mf 统计: min=1.000000  max=1.000000  mean=1.000000  std=0.00000000
mf == 1.0 的比例: 100.0000%
close == high 的比例: 100.0000%
→ big_money_net ≡ 100 × amount / 近20日均成交额
```

**后果链**：

1. 该因子实际是「成交额相对20日均值的倍数」，与 `volume_ratio`（当日量/近5日均量）**同源**；
2. Spearman 相关实测：`rel_turn ~ big_money_net` ρ = **+0.988**，`volume_ratio ~ big_money_net` ρ = **+0.758**；
3. 即：**「筹码资金基因」模块（权重 10）实质是「量价基因」模块的重复计权**；
4. README 中「主力大单净流入估计」的表述**与代码行为完全不符**，属误导性命名。

**结论**：**删除该因子**。四大基因中有两个是同一个东西，这是 v2 因子体系的结构性缺陷，不是调参能解决的。

### A2 · `bomb_times` 因子在训练集中 100% 缺失

**位置**：`build_dataset.py:460`、`build_dataset.py:474`；数据源 `build_dataset.py:147-176`

**机理**：`bomb_times` 来自东财涨停池 `stock_zt_pool_em`，而该接口**服务端仅保留最近约 15 个交易日**（代码注释自认，`build_dataset.py:148`）。
`stage1_em_pool(days=18)` 只拉 18 天，而建模样本跨 2022-11 ~ 2026-09。

**实证**（检查 1）：

```
bomb_times   all_nan=98.26%   train_nan=100.00%   nunique=20
```

**实证**（检查 10）：

```
bomb_times → quantile_bins = null （训练集有效样本 < 50，打分被强制置为中位 50）
```

**后果**：

1. 该因子在训练中**恒为中性 50 分**，零信息量，却占据 `sub_weights` 中的权重槽位；
2. 在**实时**路径中（`dragon_analyzer.py:344`）它却有真实值 → **训练分布与推理分布不一致**，属隐性偏差；
3. 由它衍生的风险规则也是空的：`check_veto` 中「反复炸板 ≥3 次」「尾盘炸板」在**历史回测里永不触发**（历史样本该字段为空）。

**结论**：**删除该因子**。炸板信息仅保留在实时路径作风险提示，历史路径一律输出 `unknown`，**禁止用默认值伪造**。

### A3 · `ret_next_oc` 不是可实现收益，且存在不可成交假设

**位置**：`build_dataset.py:550`

```python
ret_oc.append((cl / op - 1) * 100 if op > 0 else np.nan)   # 次日开盘买→收盘卖
```

#### A3.1 交易制度层面

`T+1 开盘买入 → T+1 收盘卖出` 在时间上不违反 T+1 制度（买入当日确实不能卖），
但它是**「T 日收盘看到信号 → 次日开盘买入 → 当日收盘卖出」**，属于**当日冲销型**持有期，
与「首板识别 + 次日开盘介入」的产品叙事（持有到次日/第三日）不一致，
且它是 A 股短线中**期望值最差的介入口径之一**。

**实证**（检查 7）：

```
ret_next_oc     mean=−0.296%  median=−0.486%  胜率=42.6%
ret_next_high   mean=+3.955%  median=+3.117%  胜率=85.9%
```

解读：T+1 开盘介入后**盘中最高平均有 +3.96% 的空间，但收盘只剩 −0.30%**。
典型「高开低走」。而 v2 全系统只优化 `ret_next_oc`，等于**主动选择了最差的口径**。

#### A3.2 可成交性层面（**v2 完全未考虑**）

**实证**：次日开盘价相对 T 日收盘价的分布（11,318 条匹配样本）：

```
mean=+1.856%  median=+1.076%  <0占比=29.3%  >+5%占比=17.9%  ≥+9.8%(涨停开)占比=7.33%
```

**7.33% 的样本在 T+1 以涨停价开盘 —— 此时根本买不到。**
且这批样本恰恰是**最强、最可能晋级**的那批，被 v2 一律按「开盘价成交」计入回测，
导致回测结果**系统性乐观**。

**结论**：
- `ret_next_oc` 降级重命名为 `intraday_mark_return`，**仅表示浮盈浮亏标记**；
- **禁止**继续把它当作实盘策略收益；
- 新增可成交性硬约束（`tradable_t1_open`）。

### A4 · 「70 分」是人为仿射拉伸的产物，不是统计结论

**位置**：`model_train.py:79, 183-194`、`dragon_analyzer.py:190-192`、`config.json:57-59`

```python
TARGET_SD = 15.0                       # 分数拉伸目标标准差
def apply_stretch(tot, mu, k):
    return np.clip(50.0 + (np.asarray(tot) - mu) * k, 0.0, 100.0)
```

代码注释自认：「12 个分位因子加权平均后分数会向 50 收敛（标准差仅约 8），
直接套用 70 分门槛几乎不可达，故做仿射拉伸使分布重新展开。」

**这就是问题的核心**：不是因为数据表明「70 分以上更优」，所以设 70 分门槛；
而是先决定要用 70 分门槛，再**把分数拉伸到能让门槛显得合理的尺度**。
阈值与分数尺度互为因果，**没有任何统计依据**。

**实证**（检查 5）：

```
train 入选占比 4.29%   |  valid 入选占比 5.95%  |  test 入选占比 13.77%
```

同一「70 分」阈值，在三个时期的入选率相差 **3.2 倍**。这是因为拉伸参数
`score_center=34.24 / score_scale=1.75` 是**在训练集上拟合的常数**，而各期分数分布不同。
**结论：该阈值不可移植，随时间失效。**

**结论**：删除 `score_center` / `score_scale` / `TARGET_SD`；阈值改为**训练窗口内的分位数**表达。

### A7 · 盘中扫描首板 = 训练/推理口径错配（**产品逻辑级错误**）

**位置**：`flask_server.py:184, 202-211`、`dragon_analyzer.py:264-352`

```
TRADE_WINDOW = (9*60+15, 15*60)   # 仅在 09:15–15:00 扫描
```

**机理**：

| | 训练样本定义 | 实时扫描对象 |
|---|---|---|
| 「首板」 | **收盘封板**（`close>=lim` 且 `close>=high`，`build_dataset.py:306`） | **扫描时刻正在封板**（`dragon_analyzer.py:409`） |
| 换手率 | 全日换手 | 半日/部分换手 |
| 涨停家数 | 全日 47 家 | 10:00 时可能仅 10 家 |
| 炸板率 | 全日 | 部分 |

**后果链**：

1. **样本分布外推**：模型在「全日封板」样本上训练，却被喂「半日特征」，**系统性偏差**；
2. **冰点误判**：`emotion_cycle` 在早盘因 `zt_count` 偏低会频繁判定「冰点」→ `status="暂停"`。
   例如 10:00 全市场仅 10 家涨停 → `zt<20` → 冰点 → 整个早盘扫描**几乎全部暂停**。
   **这是一个在实战中直接导致系统早盘完全失效的逻辑错误**；
3. **根本矛盾**：T 日是否「收盘封板」这一事实，**在 T 日 15:00 之前不可知**。
   所以「盘中扫描首板」在逻辑上无法与训练口径对齐。

**结论**：v3 **取消盘中扫描首板**，改为「T 日盘后生成候选池 + T+1 竞价重排序」。
这不是功能删减，而是**把产品逻辑放回它本来能成立的位置**。

## 二、B 级问题（重要 · 影响结论可靠性）

### B1 · 日K不复权，除权日涨停价判定错误
`build_dataset.py:194`、`dragon_analyzer.py:379` 均使用 `adjust=""`（不复权）。
`lim = round(preclose × (1+限幅), 2)`，其中 `preclose` 取自 `shift(1)["close"]`。
除权日价格跳变 → 涨停价计算错误 → **该日的真实涨停被漏判**（样本缺失）。
代码仅用 `bars.loc[bars["pct"].abs() > 0.35, "pct"] = np.nan`（`build_dataset.py:318`）做兜底，
但该处理发生在 `zt` 判定**之后**（`:306`），**无法阻止误判**。

### B2 · 股票池使用「当前」ST 名单过滤 3 年历史（时点无效 universe）
`build_dataset.py:229-231`：
```python
pool = [c for c in name_map
        if board_of(c) >= 0 and "ST" not in name_map[c] and "退" not in name_map[c]]
```
`name_map` 来自 `stock_info_a_code_name()`（**当前**快照）。后果：
- 历史上曾 ST、现已摘帽 → 全历史被保留（可接受）
- 现在 ST、历史正常 → **全历史被剔除** → **幸存者偏差 / 前视偏差**

### B3 · 股票名称用当前名单回填历史
`build_dataset.py:482-483` `_nm()` 返回当前名称；数据集 `name` 列与前端展示均为**未来名称**。

### B4 · 无任何交易成本
全项目无 cost 模块。佣金、最低佣金（5 元）、印花税、过户费、滑点**全部缺失**。
对「T+1 开盘买、T+1 收盘卖」这种高频换手策略，成本是决定性的：
按 0.25‰佣金双边 + 0.5‰印花税卖出 + 1‰×2 滑点估算，**单笔往返成本约 0.35%**，
而 `ret_next_oc` 均值本身只有 −0.296% —— **成本量级 > 收益量级**。

### B5 · 无 Walk-Forward
仅单次 train/valid/test 切分。无法判断「因子效果是否随市场环境变化」。

### B6 · 无基线对比
未与「全部首板随机参与」「每日随机选 3 只」「简单规则基线」做对比。
因此**无法证明复杂模型是否真的优于简单规则**。

### B7 · 「最大回撤」口径错误
`model_train.py:266-272`：按日取所选标的的**等权平均收益**，再 `cumprod` 得资金曲线。
缺失：仓位约束、同时持仓数上限、现金管理、份额取整、复利限制。
这不构成真实资金曲线，回撤数值不可用于风险判断。

### B8 · 剔除「大盘暴跌日」的口径粗暴且未验证
`build_dataset.py:381-382`：
```python
crash_days = set(mkt.index[mkt["mkt_ret"] < CRASH_DROP])   # mkt_ret = 全市场中位数日涨跌幅
```
`mkt_ret` 是**中位数**涨跌幅 < −5% 才触发，A 股极少出现 →
该规则几乎不生效，属**无效清洗**。且为何剔除当日全部样本，没有统计依据。

### B9 · 因子方向全部人工硬编码
`model_train.py:55-72`、`dragon_analyzer.py:40-48`：
```python
"price_pos": ("price", -1),   # 人为规定「越小越好」
```
12 个因子的方向均为人工指定，**从未从数据验证**。
若某因子实际方向相反（例如弱市中的「低位」并非更好），权重搜索会在**错误的方向上做优化**。
这与计划「不要人为固定」的原则直接冲突。

### B10 · 过拟合校验的筛选准则统计力不足
`model_train.py:314`：`if abs(k_tr["prec"] - k_va["prec"]) > 0.15: return None`
- train Top3 精度基于 n=2046，valid Top3 基于 n=345（`config.json:366-382`）；
- 15% 的绝对差在 n=345 下置信区间极宽（标准误约 ±2%），**噪声主导**；
- 结果是**随机丢弃大量权重组合**，再落到 A6 的 fallback（直接看 valid）→ 实质退化为**用 valid 贪心选参**。
